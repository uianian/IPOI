二、3.4 现金流消耗压力、盈利门控与风险托底细化

关键说明： 3.4 现金流消耗压力不是只有 18A 才启用。当前逻辑中，3.4 主要由 盈利状态决定：确认已盈利才跳过；未盈利或盈利状态未知时都会启用。 18A / 18C / biotech 主要影响 2.4 研发/商业化专项，以及法务侧 3.5 管线风险。

1. 盈利状态分支

判断结果后续动作注意事项
已盈利 跳过未盈利专属的现金消耗 3.4；仍分析盈利质量、现金流与偿债。 只有“最近完整年度盈利”才视为已盈利。
未盈利 启用现金消耗与现金跑道计算；连续亏损、CFO 负值进入规则托底。 18A 公司常见未盈利，但仍需识别现金压力。
盈利未知 不默认当作已盈利；继续启用 3.4，报告里标注可信度限制。 避免因为 NET_LOSS 缺失而误跳过现金压力分析。

2. 现金跑道分支

跑道区间规则含义分数影响
< 12 个月 短期资金压力明显，需要重点提示融资依赖或持续经营压力。 +20
12–24 个月 不算立即断粮，但仍存在中期融资压力。 +10
> 24 个月 现金储备相对充足，不触发跑道扣分。 0
无法计算 保留“指标缺失”说明，不凭空给出跑道结论。 按可用规则处理

三、运行模式、异常与汇合规则

默认 ReAct 路径

LLM 多轮决定下一步：先召回财务证据，再抽数、推导门控、必要时补上下文证据，最后提交完整财务分析。

汇合点：提交后统一进入规则托底。

单次 LLM 路径

用户指定 --finance-pipeline 或 ReAct 不可用时，系统先抽数和门控，再让 LLM 一次性分析。

若单次 LLM 失败，继续降级到规则路径。

纯规则路径

用户指定 --finance-rules-only 或 LLM 完全不可用时，不调用模型，直接用规则给出可解释分数。

适合无 API key、模型故障或回归测试。

统一汇合点： 无论是 ReAct、单次 LLM，还是纯规则，最终都会汇合到同一类输出： risk_score、risk_level、score_breakdown、 metrics、gates、evidence_summary 和推理日志。

四、规则托底覆盖的所有硬信号

风险信号 触发条件 分数 处理细节
CONTINUOUS_LOSS 完整年度序列显示持续亏损 +25 若同时存在单年亏损，不重复叠加单年项。
SINGLE_YEAR_LOSS 最近完整年度亏损，但未构成连续亏损 +15 只看完整年度，不把中期列当全年。
CFO_NEGATIVE 经营活动现金流持续为负 +15 属于硬信号，会防止模型把风险压得过低。
GP_MARGIN_DROP 毛利率下降超过 5 个百分点 +10 适用于有收入与毛利的发行人；18A 无产品收入时可能不触发。
CASH_RUNWAY_LT_12 未盈利且现金跑道不足 12 个月 +20 现金优先用最新一期；中期 CFO 按 8 个月年化。
CASH_RUNWAY_12_24 未盈利且现金跑道在 12–24 个月 +10 提示中期融资压力，不等于立即高危。
BURN_YOY_UP_30 现金消耗同比上升超过 30% +15 优先同口径中期对比；否则用完整年度对比。

五、证据与口径处理的特殊情况

表格解析成文本

不直接判失败。系统会按行标签和年份继续抽取，让文本型主表也能进入分析。

贵公司资产负债表

TBL_BS_COMPANY 单独作为证据展示，不混入综合资产负债表，避免口径污染。

18A 无产品收入

保留 OTHER_INCOME，不把“其他收入及收益”误当主营收入 REV。

中期列

如 2025_i1 只作为中期，不进入完整年度盈利门控；现金跑道可使用最新中期现金。

指标缺失

缺失时报告中保留说明，不默认盈利、不默认现金充足，也不编造不存在的指标。

LLM 叙述偏低

若最终规则托底后风险等级高于模型措辞，会追加注释，提示以最终等级为准。

六、最终输出物

输出用途读法
.runtime/*_finance_legal.json 机器可读结果，包含完整 metrics、gates、features、trace。 用于调试、二次分析和报告生成。
