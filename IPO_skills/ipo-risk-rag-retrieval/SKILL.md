# 招股书风险证据检索（RAG）

对应赛题任务1"金融RAG检索"部分及任务3"精准映射至招股书原PDF页码"的要求
（负责人：吴倩倩）。

## 核心定位：不是问答，是证据定位

普通RAG的目标是"回答问题"；本skill的目标是"给定一个风险结论，找到能证明它的
原文出处"。两者的关键区别：

- 输出必须包含 `page`（页码）+ 具体文本/表格片段，而不能只给一段泛化摘要；
- 允许"找不到强证据"这个结果（此时应如实标注证据强度低，而不是硬凑一个不相关
  的段落充数——这会直接拉低证据召回率指标的可信度）；
- 检索单元建议按 `hk-ipo-pdf-parsing` 输出的元素级别（text/table 片段）而不是
  整页，定位精度要求高。

## 输出格式（示例）

```
风险：
现金消耗过快

依据：
招股书第127页
2023年度经营现金流 -8.2亿
```

即：`{"risk_claim": "...", "evidence": [{"page": 127, "excerpt": "...", "source_type": "table|text"}]}`

## 检索架构建议

1. **索引层**：对 `hk-ipo-pdf-parsing` 输出的每个 text/table 元素建向量索引
   （faiss-cpu），同时保留 BM25（rank-bm25）做关键词召回，两路融合（混合检索）
   ——招股书里很多风险术语（"对赌""赎回权"）是固定表述，关键词检索命中率往往
   比纯向量检索更稳，不要只依赖embedding。
2. **切块策略**：按元素切块（一个 `text`/`table` 元素一个chunk），保留其
   `page` 和 `bbox` 作为元数据，检索结果必须能直接带出这两个字段用于报告
   证据展示（供 `ipo-warning-report-generator` 使用）。
3. **查询构造**：不要直接把风险结论原样丢给检索器，应先用LLM把结论改写成
   更贴近招股书原文措辞的检索query（例如把"现金流风险高"改写为"经营活动所得
   现金流量净额"等财务术语），提升召回率。
4. **Grep工具检索**：对于有明确关键词的场景（如查找所有"对赌""赎回"相关条款），
   优先用精确关键词/正则的Grep式检索作为向量检索的补充，两者结果取并集再排序。

## 硬指标自检

- 关键证据片段召回率 ≥ 85%（能否从招股书原文准确定位到支撑风险结论的段落/表格）。
- 建议维护一份"风险结论—人工标注证据页码"的小型测试集，每次改动检索策略后
  跑一遍召回率，而不是凭感觉判断"效果变好了"。

## 输出后交给谁

- 证据结果 → 四个业务Agent（`ipo-multi-agent-orchestration`）在给出风险判断时
  必须附带调用本skill得到的证据；
- 证据结果 → `ipo-warning-report-generator` 用于报告中的截图/页码展示。
