# 港股IPO数据集探索性分析

目标：在**不逐份精读500多份招股书**的前提下，产出一份能支撑后续任务的
数据集画像 + 一批有代表性的抽样清单，供团队后续标注测试集、验证抽取
准确率（≥80%）与证据召回率（≥85%）使用。

## 分析分层：先结构化数据，再抽样PDF精读

不要一上来就开始读PDF。正确顺序：

1. 先用 `hksharedescription.csv` + `hkcompanyinfo.csv`（结构化、秒级可查）
   把2020-2025年上市公司的全貌摸清楚；
2. 再基于这份全貌，用分层抽样选出几十份有代表性的PDF去精读/联调；
3. 剩下的几百份PDF只做**轻量级批量体检**（页数、是否能被PyMuPDF/OCR正常打开、
   文件大小），不做内容级分析。

## 第一步：结构化数据画像（用 hk-market-data-toolkit 里的字段说明）

用 `S_INFO_LISTDATE` 筛出 2020-2025 年上市的证券，统计维度建议至少覆盖：

- **按年份分布**：每年上市数量，用于判断样本是否需要按年配平（尤其
  2021-2022年生物科技热潮 vs 2023年后遇冷，市场情绪Agent很依赖这种周期性）
- **是否未盈利上市**（若字段/招股书能标注18A/18C等特殊上市规则，优先标记，
  赛题明确聚焦"未盈利公司"）
- **发行规模分布**（`S_INFO_LISTPRICE` 结合发行规模字段，若数据集里有）
- **行业分布**（结合 `hkcompanyinfo.BUSINESSSCOPE` 做粗分类，不追求精确
  行业代码，够用于抽样分层即可）
- **是否已退市**（`S_INFO_DELISTDATE` 非空，做上市后表现验证时要排除或特殊处理）
- **上市后表现初筛**（若已有EOD行情，粗算首日/5日涨跌幅分布，识别出
  "破发"和"暴涨暴跌"的极端样本，这类样本对风险预警系统的验证价值最高，
  应优先入选精读抽样池）

## 第二步：招股书PDF批量体检（500+份全量跑，但只做轻量检查，不做内容分析）

对每一份PDF跑一个快速健康检查脚本，记录：
- 文件是否可正常打开、是否加密
- 总页数（判断篇幅分布，几十页的次新股 vs 数百页的大盘股招股书，
  解析策略可能需要不同）
- 是否为纯文字层PDF还是扫描件（决定要不要走OCR分支，这直接关系到
  `hk-ipo-pdf-parsing` 里提到的解析耗时预估）
- 文件命名与股票代码/公司名是否能自动匹配上 `hksharedescription.csv`
  （提前发现命名不规范、需要人工核对的文件，避免后续批量处理时静默出错）

这一步产出一张"数据集体检表"（CSV/DataFrame），而不是逐份写分析报告。

## 第三步：分层抽样，选出精读/标注样本

抽样目标：覆盖代表性维度组合，通常 30~60 份即可支撑标注测试集与
Skill/Agent联调，不需要覆盖全部500+份。建议分层维度（按优先级）：

1. **是否未盈利企业**（赛题核心关注对象，优先多选）
2. **上市后表现**：破发/暴涨暴跌 vs 表现平稳，各选一批，用于验证预警系统
   对极端案例的识别能力（这类样本的"标注价值"远高于平稳样本）
3. **篇幅/复杂度**：几十页 vs 数百页各选几份，用于验证解析Pipeline在不同
   长度文档上的稳定性
4. **年份/市场周期**：覆盖2020-2025不同市场冷热阶段，尤其覆盖港股科技板块
   流动性下降的年份（市场情绪Agent的关键训练/校验场景）
5. **已有人工标注基础的样本优先**：项目文档里已提到马宝灵整理了古茗、
   海天味业、恒瑞医药、蜜雪冰城、宁德时代、赛力斯、三一重工等招股书，
   这些应作为抽样池的种子样本，优先纳入

抽样脚本建议输出一张"样本清单表"：股票代码、公司名、上市日期、是否未盈利、
上市后表现分类、PDF页数、抽样理由（命中了哪个分层维度）——供马宝灵后续
标注测试集直接使用，而不是重新去筛。

## 常见坑

- `hksharedescription.csv` 用 `cp1252` 编码，`hkcompanyinfo.csv` 用
  `iso-8859-1`，读取时必须显式指定，否则中文字段会乱码（详见
  `hk-market-data-toolkit`）。
- `S_INFO_LISTDATE`/`S_INFO_DELISTDATE` 是整数YYYYMMDD，需要先转日期类型
  再做年份筛选，不要直接用整数区间比较（闰年/月份边界容易出错）。
- 抽样时不要只选"容易处理的"样本（比如都选文字层清晰、篇幅短的），
  这会让后续汇报的抽取准确率虚高，掩盖了真实场景（复杂表格、扫描件）
  下的系统短板。抽样池必须包含 `hk-ipo-pdf-parsing` 里记录的已知异常类型
  （竖表、复杂表格、扫描件等）对应的样本。
