# IPO 风险穿透预警报告生成

对应赛题任务3（负责人：熊梓焱做前端展示，likesnow协助报告内容，马宝灵负责
案例分析文字部分）。

## 报告应包含的最小字段集

```
公司基本信息（股票代码、上市日期、发行价、发行规模）

综合风险评分：<0-100> — <低风险/关注/高风险>（对应总控决策Agent的A/B/C级）

风险来源（按重要性排序，每条附来源Agent）：
  ① <风险点> — 来自 财务穿透Agent — 证据：招股书第<页码>页
  ② <风险点> — 来自 法务合规Agent — 证据：招股书第<页码>页
  ③ <风险点> — 来自 市场情绪Agent — 证据：<数据来源说明>

Agent推理链路摘要（可折叠展开，满足可追踪率100%要求）

上市后表现验证（若已上市，用于反向验证预警效力）：
  上市首日涨跌幅：
  上市后5个交易日涨跌幅：  ← 赛题重点关注，需加权展示
  上市后20个交易日涨跌幅：
  上市后60个交易日涨跌幅：
  是否破发：
```

## 生成流程

1. 从 `ipo-multi-agent-orchestration` 的总控决策Agent输出取风险等级与归因；
2. 从 `ipo-risk-rag-retrieval` 取每条风险点对应的证据（页码+片段/表格）；
3. 若证据来源于表格/复杂版式（`hk-ipo-pdf-parsing` 已知异常里提到的场景），
   优先展示原始页面截图而不是可能已损坏结构的提取文本；
4. 从 `hk-market-data-toolkit` 取上市后的真实行情数据做验证部分；
5. 输出格式建议同时提供：
   - 机器可读版本（JSON，供前端`ipo-agent-dashboard-ui`渲染）；
   - 人类可读版本（Markdown/PDF，供投研人员直接阅读或存档）。
   两个版本必须来自同一份数据，不要分别生成导致口径不一致。

## 证据展示原则（可解释性核心）

- 每一条风险结论都必须能点击/跳转到原文对应页码，不允许"我们认为该公司现金流
  紧张"这种无出处的结论出现在最终报告里；
- 若某条风险的证据召回置信度较低（比如只找到弱相关段落），必须在报告中标注
  置信度，而不是伪装成强证据；
- 上市后表现验证部分是"反向验证"，用于说明预警系统的业务参考价值，
  报告中应明确写出"预警是否命中"（如：预警为高风险，上市5日内确实下跌超过X%，
  视为命中一次样本），便于后续统计整体命中率。

## 输出后交给谁

- JSON版本 → `ipo-agent-dashboard-ui`（前端渲染风险报告页）
- Markdown/PDF版本 → 直接交付给投研人员/评委作为案例分析报告
