# 招股书风险证据检索（RAG）

对应赛题任务1"金融RAG检索"部分及任务3"精准映射至招股书原PDF页码"的要求
（负责人：吴倩倩）。

## 核心定位：不是问答，是证据定位

普通RAG的目标是"回答问题"；本skill的目标是"给定一个风险结论，找到能证明它的
原文出处"。两者的关键区别：

- 输出必须包含 `page`（页码）+ 具体文本/表格片段，而不能只给一段泛化摘要；
- 允许"找不到强证据"这个结果（此时应如实标注证据强度低，而不是硬凑一个不相关
  的段落充数——这会直接拉低证据召回率指标的可信度）；
- 检索单元建议按 `hk-ipo-pdf-parsing` 输出的元素级别（text/table 片段）而不是
  整页，定位精度要求高。

## 输出格式（示例）

```
风险：
现金消耗过快

依据：
招股书第127页
2023年度经营现金流 -8.2亿
```

即：`{"risk_claim": "...", "evidence": [{"page": 127, "excerpt": "...", "source_type": "table|text"}]}`

## 检索架构建议

1. **索引层**：对 `hk-ipo-pdf-parsing` 输出的每个 text/table 元素建向量索引
   （faiss-cpu），同时保留 BM25（rank-bm25）做关键词召回，两路融合（混合检索）
   ——招股书里很多风险术语（"对赌""赎回权"）是固定表述，关键词检索命中率往往
   比纯向量检索更稳，不要只依赖embedding。
2. **切块策略**：按元素切块（一个 `text`/`table` 元素一个chunk），保留其
   `page` 和 `bbox` 作为元数据，检索结果必须能直接带出这两个字段用于报告
   证据展示（供 `ipo-warning-report-generator` 使用）。
3. **查询构造**：不要直接把风险结论原样丢给检索器，应先用LLM把结论改写成
   更贴近招股书原文措辞的检索query（例如把"现金流风险高"改写为"经营活动所得
   现金流量净额"等财务术语），提升召回率。
4. **Grep工具检索**：对于有明确关键词的场景（如查找所有"对赌""赎回"相关条款），
   优先用精确关键词/正则的Grep式检索作为向量检索的补充，两者结果取并集再排序。

## 财务 Agent（2.1 / 2.2 / 2.3）：按表类型整表召回

标准化财务指标（营业收入、毛利、总资产、CFO…）在招股书里就是三张主表里的行：

| 章节 | 表类型 | 表名线索（例） | 覆盖字段（例） |
|------|--------|----------------|----------------|
| 2.1 | 损益表 | 綜合損益表 | REV / COGS / GP / SG&A / NET_LOSS … |
| 2.2 | 资产负债表 | 綜合財務狀況表 | TOTAL_ASSETS / NET_ASSETS / CASH_EQ … |
| 2.3 | 现金流量表 | 綜合現金流量表 | CFO / CFI / CFF / END_CASH |

**硬性策略（相对旧「每字段 Top-K + 行名 Grep 取数」）：**

1. **召回单元是表，不是字段**。每种表类型做一次混合检索，返回 **附录一** 主表整表包
   （`appendix_only: true`；概要/正文不再作为财务主表来源）。
2. **直接返回整张表/表体全文**（含 HTML；解析误标为 `text` 时允许 `allow_text_as_table`），
   不要在检索层按行 role 切片取数。抽数交给下游 `ipo-risk-feature-extraction`。
3. **精准度**：除表名外，用文档 2.1/2.2/2.3 **核心行名**（`row_labels` +
   `must_have_groups`）门控，并做表类型互斥（BS≠CF≠税项附注；排除「貴公司財務狀況表」）。
4. **跨页**：现金流量表等用 `cross_page_continue` 打成连续 pack（如 mixue P437–P440），
   重叠 pack 合并为最早种子 + 最长跨度。
5. **一份策略全公司复用**：不要为发行人单独写 profile；用「綜合/合併」表名别名 +
   CF/BS 行名别名表吸收差异。规范文档：
   `retrieval/configs/finance_table_retrieval_strategy.md`；
   配置：`retrieval/configs/agent_retrieval_profiles.yaml`；
   代码：`retrieval/src/retrieval/agent_simulator.py` + `evidence_expand.py`。
   （`agents/ipo/` 为历史副本，未强制同步。）

## 硬指标自检

- 关键证据片段召回率 ≥ 85%（能否从招股书原文准确定位到支撑风险结论的段落/表格）。
- 建议维护一份"风险结论—人工标注证据页码"的小型测试集，每次改动检索策略后
  跑一遍召回率，而不是凭感觉判断"效果变好了"。

## 输出后交给谁

- 证据结果 → 四个业务Agent（`ipo-multi-agent-orchestration`）在给出风险判断时
  必须附带调用本skill得到的证据；
- 证据结果 → `ipo-warning-report-generator` 用于报告中的截图/页码展示。
